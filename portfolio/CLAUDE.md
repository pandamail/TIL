# CLAUDE.md — portfolio 운영 가이드

## 목적

IBST 인턴부터 현재 경남테크노파크 근무까지, 이력·포트폴리오를 하나의 마크다운 문서로 계속 갱신해 다음 이직 준비 시 바로 쓸 수 있도록 유지한다.
기존 PPT 포트폴리오는 IBST 인턴 내용까지만 만들어져 있고 그 이후로 업데이트가 끊겨 있었다 — 이 폴더에서 그 공백을 메운다.

## 원본 파일 관리

- PPT·HWP·PDF 원본은 git에 올리지 않는다. 개인 PC에만 보관한다.
- 이 폴더에는 마크다운으로 변환한 요약본만 둔다. GitHub에서 바로 읽히고, 무엇을 언제 추가·수정했는지가 git diff/이력 자체로 남는다는 장점이 있다.
- 원본 파일 내용을 받을 때(붙여넣기, 스크린샷, 파일 업로드 등 어떤 형태든), 그 내용을 그대로 옮기지 말고 이 문서 형식에 맞게 정리해서 반영한다.

## 구조

```
portfolio/
├── CLAUDE.md
├── README.md
└── 이력-포트폴리오.md   # 단일 문서로 관리, 섹션별로 갱신
```

## `이력-포트폴리오.md` 구성 (제안)

1. 한 줄 요약 / 핵심 역량
2. 경력 타임라인 (IBST 인턴 → 경남테크노파크)
3. 프로젝트·성과 하이라이트 — 각 항목은 근거가 되는 TIL 문서로 링크 (예: `01_Infrastructure`의 SimMonitor 아키텍처, `04_PublicSector`의 사업생애주기 등)
4. 기술·역량 스킬셋
5. 업데이트 로그 — 날짜별로 무엇을 추가·수정했는지 한 줄씩

## 작성 원칙

- 대외 공개 문서이므로 루트 `CLAUDE.md`와 `04_PublicSector/CLAUDE.md`의 포함금지 기준(기업명·금액·개인 실명·미공개 내용)을 동일하게, 오히려 더 엄격하게 적용한다 — 포트폴리오는 채용 담당자가 실제로 읽는 문서다.
- 성과는 구체적으로 쓰되, 공공기관 근무 관련 내용은 `04_PublicSector` 문서에서 이미 일반화해둔 표현을 그대로 재사용한다.
- 새 항목을 추가할 때마다 "한 줄 요약"이 최신 상태를 반영하는지 확인한다.

## 업데이트 시점

- IBST 인턴 핵심 요약: 원본 PPT 내용을 받는 대로 최초 1회 정리
- 경남테크노파크 근무: 분기별 또는 이력 갱신이 필요한 시점(이직 준비 등)마다 섹션 추가
- 애매하면 추측해서 쓰지 말고 먼저 사용자에게 확인한다 (루트 `CLAUDE.md`의 No Silent Creation 원칙과 동일).
